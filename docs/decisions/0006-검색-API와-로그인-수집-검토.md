# 0006. TikTok·Instagram: 공식 API를 끄고 검색 API로 바꾼다. 로그인 브라우저 수집은 하지 않는다

- 날짜: 2026-11-25
- 상태: 채택
- 관련: 0001(oEmbed 기각, 실제 SNS 스크래핑 금지), 0005(YouTube 재도입)

## 배경

지원자의 요청은 세 가지였다.

1. TikTok·Instagram 공식 API는 계정이 필요하니 잠시 끈다.
2. 대신 구글 검색에 `site:tiktok.com`, `site:instagram.com`을 붙여 최근 게시물을 찾는다.
3. Playwright로 일반 계정에 로그인해 수집하는 방식도 검토한다.

## 결정 1: 공식 API는 토큰이 있을 때만 켠다

- 토큰이 없고 검색 API 키가 있으면 공식 어댑터(`tiktok-research`, `instagram-graph`)로 새 수집을 하지 못하게 막는다. 가드의 capability 검사가 막고, 계획자에게도 실행할 수 있는 어댑터만 알려준다.
  - 근거 코드: `agent/availability.ts`
- 키가 하나도 없을 때는 지금까지처럼 녹화 데모로 동작한다. 정적 스냅샷과 `npm run demo:fail`도 마찬가지다.
- 이유: 녹화본을 실제 데이터 옆에 같은 자격으로 두면 가상 지표가 실제 집계에 섞인다.

## 결정 2: Google 대신 Tavily Search API를 쓴다 (AI 제안 수정)

- AI가 처음 낸 제안은 Google Custom Search JSON API였다. 문서를 확인해 보니 신규 고객을 받지 않았다(2026-11 확인). 그래서 **수정**했다.
- 같은 역할을 하는 Tavily를 골랐다.
  - `include_domains: ['tiktok.com']`가 `site:` 연산자와 같은 역할을 한다. 기본값이 restrict다.
  - `time_range: 'week'`와 `filter_by_published_date`로 최근 1주 게시물만 받는다.
  - 무료 요금제는 월 1,000크레딧이고 카드 등록이 필요 없다.
  - 문서: https://docs.tavily.com/documentation/api-reference/endpoint/search
- 이 경로의 한계는 화면(사이드바, 출처 배지 "검색 API")과 README §6에 그대로 적었다.
  - 검색 엔진이 색인한 게시물만 나온다.
  - 조회수·좋아요는 없다. 지표는 `null`로 두고 0으로 채우지 않는다.
  - 게시일은 Tavily의 추정값(베타)이다. 게시일이 없으면 결과를 버린다. 날짜를 지어내지 않는다.
- 게시물이 아닌 URL(프로필, 해시태그 페이지)은 버린다. 중복 키로는 플랫폼 고유 ID(TikTok 영상 ID, Instagram 단축 코드)를 쓴다.
- 공개 데모에서 한도를 다 쓰지 않도록 두 가지 상한을 둔다.
  - 하루 검색 상한: `SEARCH_DAILY_LIMIT`, 기본 30회. 가드의 quota 검사가 지킨다.
  - 432·433(요금제 한도) 응답은 재시도하지 않는다.

## 결정 3: 일반 계정 로그인 + Playwright 수집은 만들지 않는다 (기각)

기술적으로는 된다. 하지만 아래 이유로 기각했다.

- **약관**
  - TikTok 이용약관(미국, 2026-07-15 개정) 3.4항: "scrape, crawl, export or otherwise extract any data or content … using any automated system or software, including automated 'bots,' except as approved in writing"
  - 같은 약관 3.2항: 계정 접근을 다른 사람에게 주지 말라고 한다.
  - Instagram 이용약관(https://help.instagram.com/581066165581870)도 허락 없는 자동 수집을 금지한다고 알려져 있다. 다만 이번에는 페이지 본문을 읽지 못해 원문을 인용하지 않는다.
- **채용 맥락**: 지원하는 회사에 "약관을 어기는 수집기"를 제출하게 된다. 공고가 요구하는 것은 수집의 안정성과 대응력이지 우회가 아니다.
- **운영**: 공개 서버(Render)에 로그인 정보를 둬야 한다. 계정 정지, CAPTCHA, 2단계 인증 때문에 "접속하면 늘 동작"이라는 목표와도 맞지 않는다.
- **대신 보여주는 것**: 브라우저 자동화 역량은 저장소 안의 가상 피드(`fixtures/mock-feed/` v1→v3)로 보여준다. 셀렉터 0건과 값이 빈 필드를 감지하는 기능이다. 0001의 "실제 SNS 스크래핑 금지"를 유지한다.

## 결정 4: 라이브 서버의 시드

- 실제 수집 키(YouTube, Tavily) 중 하나라도 있으면 시드를 실제 데이터로 만든다.
  - 서버가 뜰 때 YouTube 2회와 검색 3회를 실행한다.
  - 녹화된 공식 API 시나리오는 넣지 않는다.
  - Claude 키가 있으면 실제 데이터로 계획을 한 번 받아 둔다.
- 실제 수집이 0건이면(키 오류, 한도) 녹화 시드로 대체한다. 실패한 실제 수집 기록은 운영 화면에 남긴다.

## 확인한 것과 확인하지 못한 것

- **확인**
  - 문서 형식 픽스처로 어댑터, URL 판별, 중복, 오류 분류, 가드 테스트 7개를 돌렸다.
  - 마이그레이션 005를 빼면 테스트가 CHECK 제약 오류로 실패하는 것을 확인했다.
  - 기존 로컬 DB 사본에 005를 적용했다. 행 수가 같고 외래키 오류가 없었다.
  - 잘못된 키로 실제 Tavily를 호출했다.
    - 401과 문서대로의 오류 본문(`detail.error`)이 와서 `auth`로 분류됐다.
    - 시드가 녹화 데이터로 대체되는 것도 확인했다.
- **미확인**: 유효한 키로 실제 결과를 받는 경우. `published_date`가 TikTok·Instagram 결과에 얼마나 붙는지도 모른다. 대부분 비어 있으면 결과 대부분이 "게시일 없음"으로 버려진다. 키를 받으면 가장 먼저 이것을 확인한다.
