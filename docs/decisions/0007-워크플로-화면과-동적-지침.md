# 0007. 화면을 마케터 워크플로와 Admin으로 나누고, 초안 단계와 동적 지침을 더한다

- 날짜: 2026-11-25
- 상태: 채택
- 관련: 0003(에이전트 루프), 0005(기획안 층)

## 배경 (지원자 피드백)

- "수집, 기획안, 운영상 조치가 한 화면에 있어서 헷갈린다."
- 사이드바를 **레퍼런스 수집 → 콘텐츠 기획 → 초안 발행** 워크플로로 나눠 달라.
- 에이전트가 제안한 수집을 승인하면 실시간으로 반영되는지 연결이 잘 안 보인다.
- 운영 조치는 사이드바 맨 아래 Admin으로 옮기고, 운영 조치 목록과 기획 프롬프트를 동적 설정으로 고칠 수 있게 해 달라.

## 결정

### 1. 같은 AI 호출, 종류별로 다른 화면
AI 호출은 지금처럼 한 번에 기획안·수집 제안·운영 조치를 낸다. 호출을 나누면 비용과 대기 시간이 두 배가 된다.
대신 결과를 종류별로 해당 단계에 보낸다.
- 기획안 → ② 콘텐츠 기획
- 수집·재실행 → ① 레퍼런스 수집
- 운영 조치 → Admin · 운영 조치

호출 결과 패널에는 "기획안 N → · 수집 제안 N → · 운영 조치 N →" 링크를 보여준다.
사이드바와 단계 표시에는 단계별로 사람이 처리할 건수를 붙인다 (`features/workflow/counts.ts`).

### 2. 수집 승인 → 데이터를 한 화면에서 잇는다
- **이전**: 수집 제안은 별도 "제안 검토" 화면에 있었다. 승인하면 "실행 #N" 링크만 운영 모니터로 걸렸다.
- **지금**: 수집 제안 카드는 레퍼런스 화면 안에 있다. 승인하면 서버가 그 요청 안에서 수집을 실행한다(이전과 같은 경로).
  - 응답의 `resultRunId`로 표를 그 실행이 가져온 콘텐츠로 좁힌다.
  - 처음 들어온 행에는 "새로 수집"을 표시한다.
  - 이를 위해 콘텐츠에 `firstSeenRunId`·`lastSeenRunId`를 노출했다. DB에는 이미 있던 값이다.
- 새로 가져온 것이 0건이면 빈 표 대신 이유를 보여준다. 실제로 검색 결과가 모두 기간 밖이던 경우가 있었다.

### 3. ③ 초안 발행 단계 (새로 추가)
- 채택(approved)한 기획안에서만 초안을 만든다.
- Claude가 장면별 대본·캡션·해시태그를 쓴다. 예산 밖이거나 키가 없으면 템플릿 초안으로 대체하고 그 이유를 표시한다.
- 초안에도 기획안 사양 칸과 같은 숫자 규칙을 적용한다 (`specNumberProblems`로 공유).
- 마케터가 고친 본문도 발행 직전에 다시 검사한다. 사람이 쓴 문장이라도 검증되지 않은 데이터 수치가 최종본에 들어가지 않게 하기 위해서다.
- **발행 = 최종본 확정**이다. 실제 SNS 게시는 하지 않는다.
  - 승인 없이 외부로 나가는 경로를 만들지 않는다는 원칙(AGENTS.md)을 지킨다.
  - 실제 게시는 계정·약관이 걸린 별도 결정이다 (0006).
- DB CHECK: 발행·폐기는 결정자와 시각이 있어야 하고, 폐기는 사유가 있어야 한다.

### 4. Admin · 에이전트 설정 (동적 지침)
- 프롬프트를 둘로 나눴다 (`agent/prompts.ts`).
  - **고정 규칙**(`*_RULES`): 근거 인용, 숫자, 정책 규칙. 코드에 있고 화면에서는 읽기만 가능하다.
  - **지침**(guidelines): 톤, 타깃, 형식. Admin에서 고치면 다음 호출부터 반영된다.
- 지침은 덮어쓰지 않고 `agent_config_version`에 버전으로 쌓는다. 초안에는 어떤 지침 버전으로 썼는지를 남긴다.
- 라이브 데모에서는 방문자 샌드박스 DB에 저장된다. 한 방문자가 바꾼 지침은 다른 방문자에게 퍼지지 않는다.
- 지침을 어떻게 바꿔도 가드는 그대로다. 실제로 기본 지침의 "2030"이 기획안 차단으로 이어진 것을 보고 확인했다 (0002 §11).

## 기각한 대안
- **AI 호출을 단계별로 나누기**: 단계마다 Claude를 따로 부르는 방식. 비용과 대기 시간이 늘고, 관찰 사실을 두 번 만든다. 화면 분리만으로 피드백은 해결된다.
- **지침에 적은 숫자는 가드에서 허용**: 지침으로 숫자 규칙을 풀 수 있게 된다.
- **초안을 실제 SNS에 게시**: 플랫폼 계정·약관 문제(0006)가 있고, 승인 없는 외부 실행 경로 금지 원칙과도 맞지 않는다.

## 확인
- 테스트로 확인한 것
  - 채택한 기획안에서만 초안이 만들어진다.
  - 숫자 규칙(데이터 수치, 비율, 한글 수)을 지킨다.
  - 사람이 고친 본문도 다시 검사한다.
  - 두 번 발행되지 않는다.
  - 폐기에는 사유가 필요하다.
  - DB CHECK가 결정자 없는 발행을 막는다.
  - 지침이 버전으로 쌓이고, 기본값으로 되돌릴 수 있고, 길이를 제한한다.
  - 지침이 실제 API 요청의 system에 들어간다(SDK에 테스트용 fetch를 넣어 확인).
- 실제 키(Claude, YouTube, Tavily)로 라이브 서버를 띄우고 Playwright로 화면을 끝까지 눌렀다.
  1. 수집 승인 → 실행 #9 → 표가 그 실행으로 좁혀짐
  2. 기획안 채택 → Claude 초안(6초, 가드 3/3) → 발행 확정
  3. 지침 저장(버전 1)
  - 콘솔 오류는 0건이었다.
