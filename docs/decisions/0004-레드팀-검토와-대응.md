# 0004. 레드팀 검토: 가드 우회와 사람의 확인 우회, 그리고 대응

- 상태: 대응 완료 (2026-11-24)
- 검토: 독립된 AI 에이전트(레드팀)에게 코드를 읽고 실제로 실행하며 우회를 찾게 했다. 저장소는 수정하지 못하게 했다.

## 판정: "조건부 아니오"

레드팀의 판정은 "LLM이 계획만 제안하고 사람이 승인하는 **워크플로**"라는 것이었다. 에이전트라고 부르기에 모자란 점으로 세 가지를 들었다.

- 자율 반복(스케줄)이 없다
- LLM이 도구를 쓰지 않는다
- 사람의 결정이 다음 계획에 반영되지 않는다

| 지적 | 대응 |
|---|---|
| 자율 반복 없음 | `agent watch --every <분>`을 추가했다. 주기적으로 관찰 → 제안 → 가드까지 스스로 돈다. **실행은 하지 않는다**. 사람의 승인 없이 외부 호출이 일어나지 않게 하려는 의도적인 경계다 |
| 피드백 없음 | 사람의 최근 결정(거절 사유, 가드 차단 사유)을 관찰에 넣어 LLM에 넘긴다. 사람이 7일 안에 거절한 대상은 가드가 다시 올리지 못하게 막는다 |
| LLM의 도구 사용 루프 없음 | **의도적으로 범위에서 뺐다**(0003). 수집은 쿼터와 약관이 걸린 외부 호출이라 실행 직전에 사람이 확인할 지점이 있어야 한다. 대신 MCP로 외부 AI(Claude Code 등)가 `observe`와 `propose_action`을 도구로 쓰게 했다 |

면접에서는 이렇게 먼저 말한다: "LLM이 계획하고, 결정적 검증기가 거르고, 사람이 승인하는 **사람 참여형(human-in-the-loop) 에이전트**이며, 자율 실행은 일부러 막았다."

## 재현된 우회와 대응

모든 사례를 `test/agent-redteam.test.ts`에 회귀 테스트로 넣었다. 고친 부분(실행 대상 검사, 단위 거부, NFKC 정규화, 토큰 검사)을 하나씩 끄면 해당 테스트가 실패하는 것을 확인했다.

### 할루시네이션 가드 (12건 중 11건이 통과하던 문제)

근본 원인은 두 가지였다.
- 문장 속 숫자의 허용 범위가 "인용한 사실의 **모든 필드 값**"이었다.
- 숫자 추출이 ASCII 숫자만 보고, `#` 뒤에 붙은 숫자를 지웠다.

| 사례 | 예 | 대응 |
|---|---|---|
| A 단위 변환 | 건수 11을 "조회수 11만 회"로 씀 | 숫자 뒤의 만·억·천·배·%·퍼센트·x·k·m을 거부한다 |
| B 한글 수사 | "삼백만", "두 배" | 한글 수사 + 단위 패턴을 거부한다 |
| C 근거 끼워 넣기 | 쿼터 사실을 인용해 7, 30을 씀 | 문장의 숫자는 **claims에 적은 값**만 허용한다. 사람이 claims 목록에서 "무엇의 값인지"를 볼 수 있다 |
| E 전각 숫자 | "１２０건" | NFKC로 정규화한 뒤 검사한다 |
| F `#` 뒤에 숨기기 | "#240%", "#1위" | 문자로 시작하는 해시태그만 지운다 |
| G 다른 필드 빌려 쓰기 | 건수 사실의 조회 합계를 문장에 씀 | claims에 없으면 거부한다 |
| H 비율 | 15건을 "15%"로 씀 | 단위 거부에 포함된다 |
| — 실행 번호 | "실행 #99"를 근거 없이 언급 | 근거에 `run:99`가 없으면 거부한다 |

### 실행 대상 (가장 위험했던 사례)

| 사례 | 예 | 대응 |
|---|---|---|
| D 제목과 대상 불일치 | 제목은 "#recipe 수집"인데 쿼리는 다른 키워드. 승인하자 그 키워드로 수집됐다 | **target 검사를 추가했다**: 수집할 쿼리가 근거(`hashtag:<쿼리>` 또는 `related:*><쿼리>`)에 있어야 하고 제목에도 드러나야 한다. 재실행은 `run:<번호>`를 근거로 인용해야 한다. CLI 목록에 실제 실행 대상 열을 추가했다 |
| J 무관한 근거 | 아무 사실이나 인용하고 "바이럴 폭발" | target 검사가 막는다 |
| I 중복 회피 | `"ASMR "`(대문자, 공백)로 같은 해시태그를 다시 수집 | 쿼리 값을 정규화한다: NFKC, 소문자, 공백, `#` 제거. 저장된 쿼리도 같은 규칙으로 비교한다 |

### 사람의 확인 우회

| 사례 | 대응 |
|---|---|
| **검토 API CSRF**: 다른 출처의 `text/plain` POST로 승인·실행됨 (재현) | 쓰기 요청에 네 겹의 검사를 둔다. ① Host가 localhost/127.0.0.1인지(DNS 리바인딩 방지) ② Origin·Sec-Fetch-Site가 같은 출처인지 ③ JSON Content-Type인지 ④ 서버 시작 시 만든 토큰이 맞는지. 토큰은 스냅샷 응답 헤더로만 주고 CORS를 열지 않으므로, 다른 출처의 페이지는 읽을 수 없다 |
| CLI 검토자 기본값이 OS 사용자명 | `--reviewer`를 필수로 바꿨다. 승인·거절·확인은 **대화형 터미널에서 제안 번호를 다시 입력**해야 진행된다 |
| 재검증 중 임시 `blocked` 처리, 트랜잭션 없음 | 임시 상태 변경을 없앴다. 재검증과 `pending → approved` 전이를 한 트랜잭션에서 **조건부 UPDATE**(`WHERE status = 'pending'`)로 한다. 동시에 두 번 승인해도 한 번만 실행되는 것을 테스트했다 |
| 재검증이 "관찰 범위 밖으로 밀려난 근거"를 없는 근거로 판정 (재현) | 관찰 목록에 없는 factId는 DB에서 직접 계산한다(`factById`) |
| 실행 실패 시 승인 사유를 덮어씀 | `execution_error` 컬럼에 따로 저장한다(마이그레이션 003) |

## 정직하게 남긴 한계

- **숫자와 대상의 연결**: "A의 값을 B의 값처럼 쓰는 것"은 문장 의미를 이해해야 막을 수 있다. 숫자는 claims 값으로 제한하고, 화면에 `factId.field = 값`을 함께 보여줘 사람이 대조할 수 있게 했다.
- **셸을 가진 AI**: 같은 컴퓨터에서 임의의 셸 명령을 실행할 수 있는 AI 클라이언트는 사람을 흉내 낼 수 있다(예: 토큰을 읽고 curl을 보냄). MCP 서버 자체에는 승인 도구가 없다. CLI는 대화형 터미널 확인으로 경로를 줄였다. 최종 경계는 그 AI 클라이언트에 셸이나 로컬 API 권한을 주지 않는 것이다.
- **DB 직접 수정**: CHECK 제약은 값이 비었는지만 본다. 상태 전이 순서는 앱 코드가 강제한다. 단일 사용자 로컬 도구라 인증은 두지 않았다.
- **Claude 실제 호출**: 키가 없어 검증하지 못했다.
- **데모 수치**: `demo:agent`의 일부 수치(예: #5의 "실제 57")는 Chromium 실행 여부에 따라 달라진다. 브라우저를 띄우지 못하면 브라우저 단계가 실패로 기록되기 때문이다.
